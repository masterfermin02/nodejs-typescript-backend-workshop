It allows JavaScript to run outside the browser.

Event-Driven Architecture

Node uses a non-blocking event loop.

Traditional server
Request
↓
Blocking operation
↓
Response
Node server
Request
↓
Async operation
↓
Event loop handles next request

Result: better scalability for I/O workloads.

Problem Without Types

function createUser(user) {
  return user.name.toUpperCase()
}

If user.name is missing → runtime crash.
No warning at write time. No warning at compile time.

9 / 20

Same Code with TypeScript

type User = {
  name: string
}

function createUser(user: User) {
  return user.name.toUpperCase()
}

Errors are caught before running the code.
Your editor underlines the mistake the moment you write it.

What is Validation?

Validation ensures that data entering your API is correct, complete, and safe before it reaches your business logic.

  • Check required fields
  • Enforce data types
  • Validate formats (email, UUID…)
  • Apply length / range rules

Without validation

  • Crashes from missing fields
  • Corrupt data in your DB
  • Security vulnerabilities
16 / 20

Validation with Zod

import { z } from 'zod'

const createUserSchema = z.object({
  name:  z.string().min(2, 'Name must be at least 2 characters'),
  email: z.string().email('Invalid email address'),
})

// Derive TypeScript type — no duplication
type CreateUserInput = z.infer<typeof createUserSchema>

Schema and TypeScript type are always in sync — change one, the other updates automatically.

Validate Middleware

function validate(schema: ZodSchema, target = 'body') {
  return (req, res, next) => {
    const result = schema.safeParse(req[target])

    if (!result.success) {
      const errors = result.error.errors.map(e => ({
        field:   e.path.join('.'),
        message: e.message,
      }))
      return res.status(400).json({ status: 'error', errors })
    }

    req[target] = result.data
    next()
  }
}

Used on any route: validate(createUserSchema)

Custom Error Classes

class NotFoundError extends Error {
  constructor(msg: string) {
    super(msg)
    this.name = 'NotFoundError'
  }
}

class ConflictError extends Error {
  constructor(msg: string) {
    super(msg)
    this.name = 'ConflictError'
  }
}

Throwing a typed error in the service layer:

if (!user)
  throw new NotFoundError(
    `User ${id} not found`
  )

The controller just calls next(err) — the error handler does the rest.

Error Handler Middleware

function errorHandler(err, _req, res, _next) {
  if (err instanceof NotFoundError)
    return res.status(404).json({ status: 'error', message: err.message })

  if (err instanceof ConflictError)
    return res.status(409).json({ status: 'error', message: err.message })

  res.status(500).json({ status: 'error', message: 'Internal server error' })
}

// Must be registered LAST in app.ts
app.use(errorHandler)

404 — not found

409 — conflict (duplicate)

500 — unexpected error
